## Design Specificity Verdict

**Split — and it fails on the half under review.**

**LLM assessment.** The visual world is strongly product-specific and would not survive transplant. The dormant-readout decision derives from tasks and weather having no data source and from weather requiring a network call that would breach the local-and-private principle — an argument that exists only in this product. The Rams→Apple lineage is reasoned from this audience. Pop Sleeve's refusal is grounded rather than stylistic.

The chat experience is not specified at all. The complete chat specification in DIRECTION.md is one row in the §5 tree, one line in §1's table, §4.3's numbered margin turns, §4.4's achromatic reading field, and "chat behavior" listed under Preserved. Build step 4 — the chat surface, composer, overlays, and startup restyle — is a single unelaborated row covering roughly 70% of the pixels a user looks at.

Nothing written about chat depends on: a backend returning complete JSON with no streaming, conversations vanishing on reload, a one-model roster, disabled attachments, or local inference on the user's own silicon. Hand §3 through §5 to Ollama-WebUI or LM Studio and every chat-relevant line applies unchanged.

The consequence is concrete. §8 claims the red team corrected "execution drifting toward the category default." With no chat spec, step 4 will be built by re-deriving the incumbent's structure and repainting it in Braun tokens — the category default in new colours. This is already happening: `--user-message-width` was rewritten to `100%` in the token layer, a real structural decision about the user turn, made in CSS, recorded nowhere.

**Deterministic scan.** `detect.mjs --json src/components src/App.tsx` returned exit 0 with zero findings across 14 files. That clean pass is close to meaningless, and B verified why rather than reporting it as good news:

- The detector is running **degraded** — `htmlparser2`, `css-select`, `css-tree`, and `domutils` are all missing. Its own degraded banner only prints when an HTML file is scanned, so the undercount was silent on this run.
- **Token indirection defeats the regex engine.** Every `font-family` is `var(--sans)`. The scanner cannot resolve it. It would have looked equally clean pointing at Inter.
- **The project's design system never loaded.** `loadDesignSystemForCwd()` returns NO, so all four `design-system-*` rules never evaluated.
- **The registry has no rule for `backdrop-filter` or gradients at all.** The plan's most load-bearing material prohibitions are outside this tool's vocabulary and can never be mechanically verified by it.

B confirmed the detector was functional with a synthetic positive control that correctly fired `overused-font` and `dark-glow`, so the zero is a real pass over a narrow surface, not a crash.

Because the rule-based cross-reference was vacuous, B built a grep-verified one instead. The incumbent carries 17 `backdrop-filter` declarations, radial ambient washes in `shell.css` and `startup.css`, radii up to 22px and a 99px pill, and non-zero `--panel-gap` in all three density variants. The plan **fixes** every one of those by explicit clause. It is **silent** on exactly one thing: `.thread`'s `mask-image` top and bottom fade, which is an ambient wash by another name serving a legibility purpose, banned categorically by §3 with no exception written.

**Visual overlays.** None. Script injection succeeded, but screenshot capture failed twice with `the Browser pane is not displayed, so the page is not compositing frames`. No user-visible overlay was rendered and none is claimed. Static grep over the stylesheets plus token resolution was the fallback signal.

**Two corrections to the record.** My earlier claim that the app cannot pass the startup gate without the Tauri orchestrator was wrong — the orchestrator is running and `/orchestrator/status` returns 200. B then reported the gate as hard-stuck on a fresh tab with polling halted. That is also not reproducible: the long-lived tab is currently rendering the chat home. The gate opens, just slowly, because orchestrator status must reach `waiting-backend` before the health check is attempted at all. The practical upshot is better than either of us claimed: the app runs, and DOM-level inspection of built code is available for the next critique even though screenshots are not.

## Overall Impression

This is an excellent visual world attached to an unwritten chat design, and the critique target was the chat design.

What exists is genuinely good — the rationing rule stated as a countable cardinality, the dormant-readout reasoning, the re-registration specified as a fixed-edge invariant. These are better than most design documents produce, and Rev 2 made the plan stricter rather than more comfortable.

But the document specifies an instrument face and goes quiet at exactly the point where a person actually uses this product. Every one of the ten heuristics that scored 1 or 2 is about a state: waiting, failing, recovering, being interrupted, coming back. The single biggest opportunity is not a refinement of the world — it is that the world already contains the answer to its worst gap. An instrument shows real values and never fakes progress. This product knows the elapsed seconds, the model name, whether it fell back to CPU, and how many tokens came back, and it currently displays none of them while the user waits. `CPU · 0:22` during a local inference is a truth no hosted assistant can tell, and it is the most product-specific chat detail available anywhere in this brief.

## What's Working

**The rationing rule is a test, not a preference.** "Orange is the single lit thing on screen at any given moment. If two things are orange at once, one of them is wrong." Most colour sections say "use the accent sparingly," which is unfalsifiable. This one is verified by counting, so it survives review and a second contributor.

**The dormant-readout decision, and specifically its reasoning.** Replacing fabricated task rows with a precisely drawn instrument at rest that names what it waits on dissolves the honesty problem instead of disclaiming it. §5 names the alternative's failure mode — "put the honesty burden on a caption nobody reads." It is the only place in the document that reasons from a hard constraint to a form.

**Re-registration specified as an invariant rather than an animation.** Naming the edge that must not move correctly diagnoses why card-inflation reads as Android: the loss of a fixed reference, not the scaling. It is buildable, reviewable, and degrades correctly under reduce-motion. It is the one motion spec here a second person could implement without asking a question.

## Priority Issues

**[P0] The chat experience is unspecified.**
*Why it matters:* the brief was a chat redesign. There is no spec for the assistant turn, the user turn, any of the five message statuses, the composer, the thread measure, or how code blocks, tables, and lists behave inside the panel world. Step 4 will become a repaint of the incumbent — the drift §8 claims was already corrected.
*Fix:* write §5.1 before step 4 starts. Minimum contents: assistant turn bounded by tone rather than a container, using the face's own existing law — prose on `Display field`, user turns on `Raised control` with a 1px seam, full measure, no radius past 2px, no right alignment. Keep the "Maia" label as text, because it is the turn's accessible name and its only non-visual distinction. Explicit treatment for all five statuses. A ruling on `--message-user-bg` and `--user-message-width: 100%`, which the token layer already changed without record.
*Suggested command:* `$impeccable shape`

**[P0] "No indeterminate spinner" makes the most-seen state in the product unbuildable.**
*Why it matters:* §4.2 demands a fixed track; the backend supplies no position. The plan bans the honest option and mandates an impossible one. Users hit this state every single turn, and on CPU fallback it can run a minute.
*Fix:* show elapsed, not progress. A tabular-figure timer counting up is determinate, truthful, and native to an instrument — instruments show elapsed time and never fake progress. This is also a better justification for the global tabular figures than turn numbers. Add the startup screen's 20-second reassurance line at the same threshold so both waits speak one language, and state that streaming replaces the timer rather than supplementing it.
*Suggested command:* `$impeccable harden`

**[P1] Conversations die on reload and nothing acknowledges it.**
*Why it matters:* PRODUCT.md's "build for the closing gaps" is being read as silence, but this gap is destructive rather than merely absent. Cmd+R is muscle memory, and an hour of conversation disappears with no warning in either document.
*Fix:* one line at the Meta step in the control column's history region, in the voice the plan already invented for dormant readouts: held in memory for this session, stored history is coming. Not a toast — a toast is the wrong instrument for a standing condition. This also exposes whether "temporary chat" is currently a distinction without a difference.
*Suggested command:* `$impeccable clarify`

**[P2] "One orange at a time" has no precedence order and the working state has three claimants.**
*Why it matters:* focused composer plus selected conversation plus in-flight turn is not an edge case; it is the state the app is in whenever it is doing its job. §7.11 names this and stops.
*Fix:* write the precedence into §3 — in-flight beats focused beats selected — and specify the demoted expression for each, because "demote" without a fallback means "disappear," and an invisible selection is worse than two oranges. Name the neutral focus-ring token explicitly: a focus ring whose appearance depends on unrelated app state is a keyboard defect.
*Suggested command:* `$impeccable colorize`

**[P3] §4.1 and the legend ban collide with no arbitration.**
*Why it matters:* §4.1 read literally unfolds the model popover, profile menu, and Preferences permanently, while §3 simultaneously removes the uppercase micro-caps that labelled those groups — and §7.12 already admits the substitute is unproven. Two rules each remove a labelling or containment device.
*Fix:* one sentence bounding §4.1 to value sets inside an already-visible control group — things that are literally switch positions — and exempting navigational menus and the model picker, which are not.
*Suggested command:* `$impeccable layout`

## Persona Red Flags

**Alex (impatient power user)**

- **Esc does nothing during a wait.** The stop control exists in `Composer.tsx` when streaming, but it is mouse-only and no keyboard binding is specified anywhere. Alex's instinct at second 40 of a CPU response is Esc.
- **Turn numbers he can read and cannot use.** §4.3 promises "addressable and re-enterable" and specifies no address — no jump, no copy-link-to-turn. He is exactly the user who would want it.
- **The dashboard is mandatory transit to the only working surface.** Every launch routes him through an instrument panel that is two-thirds at rest to reach the thing he opened the app for. No direct-to-chat path is specified.
- **Cmd+R destroys the session** with no warning or persistence.
- **The disabled paperclip holds the most reachable composer slot**, permanently tooltipped "not supported yet." The plan does not remove it.

**Sam (accessibility-dependent, keyboard and screen reader)**

- **Margin turn numbers are a hazard either way.** Exposed, "12" is read before every turn as noise. Hidden, the addressable affordance does not exist for Sam at all. Neither document states the accessible name of a turn.
- **Turn role carried by paint alone.** If assistant and user are distinguished by surface tone, that distinction is absent from the accessibility tree. The incumbent at least renders "Maia" as text. "Minimal unnecessary containers" must not take that label.
- **The gapless face removes the only non-visual region boundary and replaces it with nothing.** §5 assigns no landmarks. `<nav>`, `<main>`, and `<section aria-labelledby>` belong in the plan, not in build-time discovery.
- **Contrast is unverified and one value is structurally suspect.** `Signal (fills) #D2540A` is identical in both themes; the same fill cannot serve content on `#EDEBE5` and on `#1A1A18` equally. PRODUCT.md sets no conformance standard, so nothing forces the check — that absence is the real defect.
- **The 10px legend is load-bearing.** It names every region on the face, at 620 weight and 0.09em tracking — below the floor desktop software normally holds, on precisely the labels Sam most needs.
- **Genuine credit:** reduce-motion is handled to a shippable standard — OS and app preference, read before React mounts, combined through `MotionConfig`, degrading to a cut.

## Minor Observations

- **A third file contradicts the document.** §6 lists `panels.tsx` and `global.css`. `chat.css` is a third: `.msg-error` uses `--danger-tint` as a filled background, which §3's "no tinted rows" bans, and the token is still defined at new palette values in both themes.
- **Naming debt.** `--composer-glass` and `--accent-gradient` persist as names while §3 bans blur and gradients; `--accent-gradient` now holds a flat hex. The names will outlive the materials and the next contributor will read them as permission.
- **`.thread`'s mask-image fade** is the one incumbent material the plan neither fixes nor exempts. It serves legibility rather than decoration and probably deserves to survive, but it needs an explicit ruling.
- **Italic sits outside the type system.** `.msg-stopped` uses it, as do markdown `em` and `del`. The six-step scale specifies size and weight and never addresses style.
- **The tabular-figures justification is thin.** Turn numbers are the contested raise; clock readings and token counts do not yet exist. The feature is right, the argument rests on its weakest leg.
- **The chat empty state is unowned.** PRODUCT.md parks quick starts there; DIRECTION.md never picks it up. Neither document owns the first screen of a new conversation.
- **`MaiaMark` as a per-turn thinking indicator** is inherited, not decided. It is a brand commitment for startup; using it as an in-thread status light should be stated, especially beside an elapsed timer.
- **The profile block has no home.** The control column replaces the rail, and the plan does not say what happens to the hardcoded name block or the "Sign out" row that toasts "Accounts arrive after the preview." In a local-only product with no account, a sign-out affordance actively misleads about where data goes.
- **Two conflicting design systems are on disk.** `design-system/maia/MASTER.md` still specifies a violet and pink palette against DIRECTION.md's Braun panel. PRODUCT.md records it as non-binding, but the detector would try to load it if its loader ever resolved.

## Questions to Consider

1. **If 90% of the surface is prose, why is the metaphor the instrument face rather than the display?** The SK4's most-copied feature is the transparent lid over the working part. If the reading field were the thing the panel exists to protect and reveal, §7.2's risk inverts instead of needing mitigation.
2. **What is a turn number for?** If the answer is "you can point at it," build the pointing and the raise earns its keep. If the answer is "it looks like an instrument," delete it — it is currently the source of three of the four cognitive-load failures.
3. **The plan bans fake progress because instruments show real values — so what are the real values?** Elapsed, model, CPU versus GPU, tokens returned. The product knows all four and shows none.
4. **If everything vanishes on reload, is every chat already temporary?** Saying so plainly is the same move §5 made with the dormant readouts.
5. **What if the dashboard shipped with one region?** Chat full width, registry intact and empty. The extensibility claim survives untouched and §7.5's composition problem disappears.
6. **"Cozy" is §7.1's weakest link — what is the mechanism?** Braun's domestic objects are cozy because they are small, tactile, and owned. What in a 1280px window is the analogue of holding it?

## Cognitive Load

**4 failures of 8 — HIGH.**

Failing: chunking (§4.1's unbounded ban on disclosure forces 10+ simultaneous controls in Preferences); grouping (the gapless face removes gutters and §7.10 admits the replacement may not work at a ~4% luminance step); working memory (a turn number carries no content, and conversations dying on reload means everything learned lives only in the user's head); progressive disclosure (actively banned by §4.1 with nothing specified to replace it).

Passing: single focus, visual hierarchy, one thing at a time, and options-per-decision.

Three of the four failures trace to a single raise, §4.1 and §4.3, and the fourth to the gapless face. Both arrived in Rev 2. The plan got stricter and more expressive and picked up its cognitive-load debt in the same move — which is worth knowing before the next round of tightening.
